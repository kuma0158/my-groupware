# 機能・サービス一覧

社内グループウェアで、現在実装されている機能の一覧です(2026-09-21 時点)。
コード(`backend/app/`、`frontend/src/`)と、これまでの引き継ぎ記録をもとにまとめています。

- 各機能の「状態」は、実装の有無を表します。ブラウザ・実機での表示確認が済んでいない項目は、末尾の「未確認・未実装」に別にまとめました。
- API の詳細は `README.md` の「API 一覧」、または起動中のバックエンドの http://localhost:8000/docs を見てください。

## 1. サービス一覧(概要)

| No. | サービス | 画面 | 主な内容 | 権限 |
|---|---|---|---|---|
| 1 | アカウント | `/login` `/register` | 新規登録・ログイン・ログアウト | 誰でも(登録) |

| 4 | ToDo | `/dashboard/todos` | カンバンボード、担当者、共有 | ログイン済み |
| 5 | インフォメーション | `/dashboard/notices` | 社内お知らせ、上部固定、既読 | ログイン済み |

## 2. 共通の仕様

- **ログイン方式:** メールアドレスとパスワード。JWT を HttpOnly Cookie に保存(有効期間は既定 24 時間)。
- **権限:** パワーユーザー / 一般ユーザーの 2 種類。最初に登録した人がパワーユーザー。
  - 権限で制限しているのはユーザー管理だけ。それ以外の機能は全員が使える。
- **無効化されたユーザー:** ログインできない。伝言の宛先にもできない。
- **画面遷移の保護:** `/dashboard` 以下は、クッキーがなければログイン画面へ戻る(`middleware.ts`)。
- **対応端末:** PC とスマホ(幅に応じて表示が変わる。スマホのドラッグは長押しで操作)。
- **見た目:** テーマ(`instrument` が既定)と、ユーザーごとのカラースキーム 4 種。

## 3. 機能の詳細

### 3-1. アカウント

- 新規登録: 名前(100 文字まで)・部署(100 文字まで)・メールアドレス・パスワード。登録するとそのままログイン状態になる。
- ログイン / ログアウト。
- メールアドレスは重複登録できない(409)。
- 新規登録は初期状態では誰にでも開いている。環境変数 `ALLOW_REGISTRATION=false` で、最初の 1 人以外の新規登録を止められる(止めると 403)。招待制や承認制の仕組みは未実装。

### 3-2. ポータル

- ウィジェット(カード)を並べたトップ画面。横 4 列(幅 900px 以下は 2 列、720px 以下は 1 列)。
- 操作: ドラッグ(スマホは長押し)で並べ替え、追加、削除、幅の切り替え(1 列 / 2 列)。
- 配置はユーザーごとにサーバーへ保存される。初回ログイン時は初期配置が入る。
- カード本文をクリックすると、対応する画面へ移動する(並べ替えは見出し部分から)。
- 1 人あたり最大 24 枚。

ウィジェットの種類(11 種):

| 種類 | 内容 |
|---|---|
| `stat.events` | 予定の件数 |
| `stat.todos` | ToDo の件数 |
| `stat.notices` | 未読のお知らせの件数 |
| `stat.messages` | 未対応の伝言の件数 |
| `schedule.today` | 今日の予定 |
| `todo.open` | 未完了の ToDo |
| `notice.latest` | 最新のお知らせ |
| `message.unhandled` | 未対応の伝言 |
| `presence.board` | 在席ボード |
| `memo` | メモ |
| `clock` | 時計 |

### 3-3. スケジュール

- 表示: 月表示(1 日あたり 3 件まで、超えた分は「ほか N 件」)と、週表示(時間軸つき)。切り替えボタンつき。
- 予定の項目: 件名(必須、200 文字まで)、日付、開始・終了時刻(15 分刻みで選択、所要時間ボタンつき)、場所(120 文字まで)、メモ、非公開。
- 追加・編集はモーダルで行う。開始時刻を変えると、終了時刻が同じ長さだけずれる。
- **自分の予定は、ドラッグで移動できる**(日時が一緒に変わる)。
- **他人の予定は読み取り専用。** 編集・移動・削除は、サーバー側でも 403 を返す。
- **非公開の予定は、本人以外には表示されない。**
- 期間の取得は最大 62 日まで。終了が開始より前の予定は保存できない(400)。

### 3-4. ToDo(カンバンボード)

- **列:**
  - 初期は「未着手 / 進行中 / 完了」の 3 列。列は**全員で共有**する。
  - 追加・名前変更・削除・並べ替え(列メニューの「左へ / 右へ移動」)ができる。
  - 最大 12 列。完了列と未完了の列は、それぞれ 1 つ以上必要(削除や種類の変更は 400)。
  - 列を削除すると、中のカードは「同じ種類で一番左の列」の末尾へ移る。
  - 列の色は、並び順で決まる(完了列は緑、未完了は赤・青などを繰り返す)。
- **カード:**
  - 追加は件名だけで作れる。担当者・期限は、作成後に詳細から設定する。
  - ドラッグ(スマホは 350ms 長押し)で列の間を移動できる。端に近づくと自動でスクロールする。
  - クリックすると、中央の小窓で詳細(件名・メモ・期限・担当者・列)を編集できる。ドラッグできない環境でも、詳細の「列」から動かせる。
  - 「完了列」に入ったカードは、完了として扱われる(件数やバッジもこれに従う)。
- **見える範囲:** 「自分が登録した / 自分が担当 / 共有された」ToDo だけ。
- **共有:**
  - 登録者が、他のユーザーへ共有できる。
  - 共有された人は、見る・動かす・内容を直すことができる。
  - **削除と共有の変更は、登録者だけ**(他の人は 403)。
  - 共有中のカードには「共有」チップが出る。

### 3-5. インフォメーション(社内お知らせ)

- 投稿(件名 200 文字まで + 本文)、削除、上部固定。
- 既読管理: お知らせを開くと既読になる。ユーザーごとに記録される。
- **自分が書いたお知らせは、常に既読扱い。**
- **削除できるのは、書いた本人だけ**(他の人は 403)。

### 3-6. 伝言・在席

- **在席状況:** 「在席 / 外出 / 離席 / 休み」の 4 種類と、ひとこと(120 文字まで)を自分で更新できる。
- **在席一覧:** メンバー全員の在席状況・部署が見られる(メールアドレスなどは出さない)。
- **伝言メモ:**
  - 他のユーザーへ、電話の相手(120 文字まで)と本文を書いて残せる(モーダルで入力)。
  - 宛先は、有効なユーザーだけ。
  - 受け取った人は「対応済みにする」で記録できる。既定では、未対応のものだけが一覧に出る。

### 3-7. 新着バッジ(上部ナビゲーション)

- ToDo・お知らせ・伝言の件数を、メニューに表示する。
- 更新のタイミング: 画面移動時、60 秒ごと、お知らせの投稿・既読・削除と、伝言の対応済みの直後。
- ToDo のバッジは、ToDo 画面に移った瞬間に消える。以降は、開いた時点の件数を超えて**増えた分だけ**出す。
  - 「見た分」はブラウザの localStorage に保存する。**端末ごと**なので、別の端末では出る。
- 他のユーザーの画面へは、即時には届かない(60 秒ごと、または画面移動時)。

### 3-8. 設定

- **プロフィール:** 名前・部署の変更(メールアドレスと権限は変えられない)。
- **パスワード:** 変更には、現在のパスワードが必要。
- **カラースキーム:** 暖色 / 中間色(標準) / 寒色 / ダークモード。アカウントごとにサーバーへ保存され、端末をまたいで同じになる。変更すると、すぐ反映される。

### 3-9. ユーザー管理(パワーユーザーのみ)

- ユーザー一覧の表示。
- 権限(パワーユーザー / 一般ユーザー)の変更。
- 有効 / 無効の切り替え。
- 守られる制約:
  - パワーユーザーは、常に 1 人以上必要。最後の 1 人は、降格も無効化もできない。
  - 自分自身は、無効にできない。
- 一般ユーザーが操作すると 403。設定画面のタブも、パワーユーザーにだけ表示される。

### 3-10. AI エージェント(`agent/`)

- グループウェア本体とは独立した、ローカル実行の雛形。コマンドラインから `python agent.py --prompt "..."` で使う。
- Azure OpenAI の環境変数を設定すると、実際のモデルで応答する。未設定のときは、固定の応答を返す。
- **本体のデータ(予定・ToDo など)にはまだつながっていない。**

## 4. 基盤・運用の機能

| 項目 | 内容 |
|---|---|
| DB の自動作成・移行 | 起動時にテーブルを作り、既存の DB に足りない項目を足す(ToDo のカンバン用項目、権限、配色)。何度起動しても安全 |
| 初期データ | 起動時に、ToDo の初期の列を作り、既存の ToDo を列へ振り分ける。パワーユーザーが居なければ、最古の有効ユーザーを昇格 |
| API ドキュメント | `/docs`(Swagger UI)を自動生成 |
| リクエスト転送 | ブラウザの `/api/*` を Next.js が FastAPI へ転送(同一オリジンで、CORS 設定が不要) |
| パスワード保護 | bcrypt でハッシュ化して保存 |
| 自動テスト | pytest 81 件(API 結合テスト)、Playwright の E2E 22 件(`e2e/`、git 管理外) |
| 公開手順 | `docs/deploy.md`(VPS への公開、バックアップ、更新) |
